## The fifth state, and why this package carries it now

AER-1 carries five states, and its `absent` means the receipt carries no member of the kind the check needs at all; the draft's own note says that state *must not collapse into an evaluated outcome*. Its vectors `anchor-absent, anchor-other-profile` are that state; `anchor-not-checked` is `not checked` (a member is present, the verifier did not evaluate it), and the draft keeps them apart because a verifier that never attempted resolution must not look like one that attempted and failed.

This package reported D03 (no scope declared) as `check-incomplete` with code `NO_DECLARED_SCOPE`, which is an evaluated outcome, and the first version of this crosswalk recorded that as the one row the two vocabularies read differently. The disagreement was resolved on the argument, not on preference: in D03 every other check passes, and attenuation could not run only because there was nothing to attenuate against, so the next step for a reader is to go and get a declaration rather than to rerun a check that completed correctly. The remedy sits with the caller, and the outcome now does too: the package carries `absent` as a fourth non-pass state, decision `hold`, exactly as AER-1's fifth. D03 reports `absent` and both directions of the crosswalk are exact.

The cost is real and is stated rather than hidden: a downstream reader of this package's results now has four non-pass words to handle instead of three, and an implementation that read the old three must add a branch. That is why the state is adopted here, where the package's authors own the vocabulary, while any wider adoption remains the decision of the group that maintains it. The boundary case is drawn at what the record asserts: a record that commits to a form it does not deliver is a `fail`, because a committed value that does not match is a finding; a record that commits to nothing is `absent`, because there is no finding to make.

## What this crosswalk does not establish

Neither side is a conformance suite for the other, and neither one vouches for the other's subject matter. AER-1 governs anchors and receipts for executed work; this package governs gateway admission under a delegated mandate. The two meet only on reachability and evaluability — what can be resolved, and what was actually checked — and that is exactly the ground the two rows are aligned on. Agreement here is evidence that two vocabularies describe the same gap the same way; it is not evidence that either implementation is correct.
